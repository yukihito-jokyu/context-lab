# Context Lab Wails E2E テスト

## 対象と境界

- UIからWails bindingを経て安全な画面状態へ戻る主要フローを検証する。
- 実験実行はDocker + `codex exec` adapterのfakeまたは専用テスト設定を使う。実Dockerは明示承認された隔離試験だけで使う。
- ACPは環境準備・壁打ちだけを扱い、通常はfake adapterを使う。
- SQLiteは一時DB、artifactは専用ディレクトリに分離する。個人の環境、資格情報、外部RDBMSは使用しない。

## 手順

1. Issueの受け入れ基準とSCR/HTML上の操作を対応付ける。画面上の全操作に実装済みの意味を確認する。
2. 起動用fixtureでtest DB、artifact root、fake Wails servicesを用意する。
3. 最低限、正常、空、入力エラー、再試行可能な失敗、実行中の状態を自動化する。
4. 「実験開始」は条件を固定した後に全プロンプト実験を自動開始する仕様を確認し、個別の不要な実行ボタンを前提にしない。
5. 失敗理由・詳細表示はボタン押下後の具体的な表示まで検証する。
6. `task frontend:e2e`を実行し、必要に応じて`task test:integration`を補助する。

## 代表フロー

| 画面 | 検証する結果 |
| --- | --- |
| 実験一覧 | 一覧・空状態・作成モーダルへの遷移 |
| 実験準備 | 環境候補選択、プロンプト追加、入力検証、条件固定 |
| 実験実行 | 開始、進行、成功・失敗・取消、詳細・失敗理由表示 |
| 評価・比較 | 評価実行、比較対象選択、結果表示、派生作成 |
| 知見 | 保存、再表示、編集失敗時の回復 |
| 環境準備 | ACP壁打ち、候補採用、接続失敗の表示 |

## 禁止事項

- 内部推論、APIキー、資格情報、Docker ID、sidecar PIDをUIやスクリーンショットの期待値に含めない。
- 実験の実行をACPへ委譲しない。
- 仕様にないダミーボタン・遷移をテストの都合で追加しない。
