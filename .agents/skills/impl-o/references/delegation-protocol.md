# 委譲プロトコル

## 実装契約

オーケストレーターは委譲前に次をまとめる。

- Issue番号、Wails関数名、query/command
- 入力・成功・失敗DTOと対象SCR操作
- 編集可能なパス、編集してはならないパス
- Docker / ACP / SQLiteの境界と機密情報の禁止事項
- 必須検証と担当間の受け渡し条件

## 依頼文の型

```text
担当: <設計確認 | Go実装 | React実装 | 検証 | 独立レビュー>
対象: Issue #<番号> / Wails関数 <名前>
契約: <入力・成功・失敗・画面操作>
所有範囲: <編集可能パスまたは読み取り専用>
制約: <安全境界・他担当との接点>
完了報告: <変更、検証、未解決事項、次担当への引継ぎ>
```

## 実装担当の分割

- Go担当とReact担当は別パスを所有する。共有DTOや生成bindingに変更が必要なら、オーケストレーターが順序と統合を決める。
- 同一ファイルを扱う必要がある場合は並行委譲せず、先行担当の完了後に次担当を起動する。
- 設計確認・独立レビュー担当は、修正を直接行わず根拠と重大度を報告する。
